Operator manual

Follow a report from intake to the team that owns it.

  • Open the read-only console to browse published cases.
  • Start a private workspace to upload your own reports.
  • Already have access? Connect the command line or your coding agent.

01Follow a finding

Open a report in the review console. The case brings the deployment, recorded checks and owner decisions into one view.

  1. Identify the deployment.

    Read the service, component and revision beneath the title. These fields come from your catalog or the authenticated upload.

  2. Inspect the evidence.

    Open a recorded run to read its CI observations. Compare runs when more than one is available. A missing observation leaves the check inconclusive.

  3. Review ownership.

    Read the suggested owners and prior decisions. In a private workspace, a reviewer can accept or reject a team. A worker assigned to the case can record the outcome of its review.

02Self-host a workspace

Start with one workspace for your organization. Docker Compose runs both the console and HydraDB on your computer. You can use it with Windows, macOS or Linux.

Get the project files

Open the Ichnix repository and choose Code → Download ZIP and extract it, or run these commands with Git installed. 

git clone https://github.com/sansynx/ichnix.git
cd ichnix

Run the setup commands from the folder containing cli.py and compose.yaml.

Docker Desktop on Windows and macOS, or Linux Compose

Start Docker Desktop with Linux containers on Windows (WSL 2) or macOS. On Linux, use Docker Engine with Compose v2. Apple silicon runs the Linux amd64 image under emulation.

  1. Start the workspace.

    Open PowerShell or a terminal in the repository folder containing compose.yaml. Run each line in order. 

    docker compose --env-file examples/desktop.env build
docker compose --env-file examples/desktop.env run --rm console python3 cli.py storage init
docker compose --env-file examples/desktop.env up --detach --wait
  2. Create an upload credential.

    Issue this token once. The second command checks that its name is desktop-intake and its role is intake. 

    docker compose --env-file examples/desktop.env exec -T console python3 cli.py identity issue desktop-intake --role intake --out /var/lib/ichnix/desktop-intake.token
docker compose --env-file examples/desktop.env exec -T console python3 cli.py auth status --workspace-url http://127.0.0.1:8765 --token-file /var/lib/ichnix/desktop-intake.token
  3. Sign in.

    Copy the token using the command for your shell below. Open your local console, paste the token, then clear the clipboard. Follow your first upload to add a report.

Copy the intake token on your operating system

PowerShell on Windows

docker compose --env-file examples/desktop.env exec -T console cat /var/lib/ichnix/desktop-intake.token | Set-Clipboard

Terminal on macOS

docker compose --env-file examples/desktop.env exec -T console cat /var/lib/ichnix/desktop-intake.token | pbcopy

Linux on Wayland with wl-copy installed

docker compose --env-file examples/desktop.env exec -T console cat /var/lib/ichnix/desktop-intake.token | wl-copy

To stop the workspace and retain its named volumes, run docker compose --env-file examples/desktop.env down. Start it again with the same up --detach --wait command. The console binds to loopback. Remote teams need a private HTTPS endpoint. For an existing installation, preserve its original storage paths.

Mount a private provider catalog in Compose

For a private program, export its connector settings from your secret manager before starting Compose. Catalog and signing-key paths must name files inside the console container. To mount a private directory, add this to a local Compose override. Grant the container user (UID 10001) read access to the required files and keep this directory outside the checkout. 

services:
  console:
    volumes:
      - type: bind
        source: /srv/ichnix/private-config
        target: /run/ichnix-config
        read_only: true
        bind:
          create_host_path: false

Set ICHNIX_CATALOG to /run/ichnix-config/catalog.json for HackerOne. Include the override when running Compose commands. Recreate the console after changing environment credentials. For a relay-protected workspace, set ICHNIX_ORIGIN_SECRET before exposing the origin and verify a direct request without the header returns HTTP 403.

Native Ubuntu 24.04 on x86-64

Install Python 3.12, Node 24 and pnpm 12. In the checkout, install the pinned dependencies and start HydraDB. 

pnpm install --frozen-lockfile
python3 scripts/install-hydra.py
scripts/start-hydra.sh

Leave HydraDB running. In a second terminal in the checkout, configure the same state directory, initialize the private stores and issue an intake token for the first upload. 

export ICHNIX_STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/ichnix"
export ICHNIX_IDENTITY_DB="$ICHNIX_STATE_DIR/identities.sqlite3"
export ICHNIX_HANDOFF_DB="$ICHNIX_STATE_DIR/handoffs.sqlite3"
python3 cli.py storage init
python3 cli.py identity issue first-intake --role intake --out "$ICHNIX_STATE_DIR/first-intake.token"
scripts/console.sh

Open your local console and sign in with the contents of first-intake.token. Keep this terminal running. Reuse the same paths and credential on subsequent starts.

Use an existing graph or change the state directory

The default state directory is ~/.local/state/ichnix. Set ICHNIX_STATE_DIR consistently to move it. For an existing graph, configure ICHNIX_HYDRA_URL, ICHNIX_HYDRA_TOKEN_FILE, ICHNIX_HYDRA_NAMESPACE, ICHNIX_HYDRA_GRAPH and ICHNIX_HYDRA_CELL. Use authenticated HTTPS for remote connections.

03Set up the CLI

The command-line interface (CLI) lets you read and submit reports from a terminal. If your organization already hosts Ichnix, you need its workspace URL, a named token, the project files and Python 3.12 or newer.

1. Open the CLI

In the folder containing cli.py, check that Python can run the command below. On Windows, use py -3 in place of python3. 

python3 cli.py --help

2. Connect your workspace

Replace the placeholder URL with the origin your administrator supplied. Use a direct connection for a self-hosted workspace. If your administrator gave you a Vercel organization relay, enable hosted mode as shown for your shell below.

Windows · PowerShell 7 or newer

Set the workspace origin, then enter the credential at the masked prompt. For a Vercel workspace, also set $env:ICHNIX_WORKSPACE_HOSTED = '1'. Use the Windows Python launcher to check your role and list the available cases. 

$env:ICHNIX_WORKSPACE_URL = 'https://workspace.example.org'
$env:ICHNIX_USER_TOKEN = [System.Net.NetworkCredential]::new('', (Read-Host 'Named workspace token' -AsSecureString)).Password
try {
  py -3 cli.py auth status --token-env ICHNIX_USER_TOKEN
  py -3 cli.py human --token-env ICHNIX_USER_TOKEN cases
} finally {
  Remove-Item Env:ICHNIX_USER_TOKEN
}

For unattended runs, have your secret manager inject the token into the client process.

macOS or Linux · terminal

Save the named token in a private file. Point the CLI at the file, then check that the workspace recognizes your name and role. For the Vercel relay, first run export ICHNIX_WORKSPACE_HOSTED=1. 

export ICHNIX_WORKSPACE_URL=https://workspace.example.org
export ICHNIX_USER_TOKEN_FILE="$HOME/.config/ichnix/reviewer.token"
chmod 600 "$ICHNIX_USER_TOKEN_FILE"
python3 cli.py auth status
python3 cli.py human cases

3. Read or update a case

Replace CASE_ID with an ID returned by human cases. The commands below use the macOS or Linux token file. For Windows, choose the PowerShell commands below the list.

  • Any human role

    Read a case and its evidence.

    python3 cli.py human context CASE_ID
  • Intake

    Submit a six-field JSON report. 

    python3 cli.py human import-report report.json
  • Review

    Record a decision. Replace TEAM with the owner under review. Reuse the request ID if you retry that same decision. 

    python3 cli.py human review CASE_ID TEAM --accept --request-id review-001
Run these commands in PowerShell

Choose the command for your role and insert it inside the try block in the Windows connection instructions above.

Read a case with a read, review or intake token:

py -3 cli.py human --token-env ICHNIX_USER_TOKEN context CASE_ID

Import a mapped report with an intake token:

py -3 cli.py human --token-env ICHNIX_USER_TOKEN import-report report.json

Accept the suggested owner with a review token:

py -3 cli.py human --token-env ICHNIX_USER_TOKEN review CASE_ID TEAM --accept --request-id review-001

04Connect a program

For your first report, use a small JSON file and an intake credential. Once the upload works, connect your platform using the matching guide below.

Upload your first report
  1. Create a UTF-8 file named report.json. Use the six fields below, replacing each capitalized value with your report metadata.
  2. Open your private console and sign in with the intake credential from workspace setup.
  3. Drop the file in the upload area or use the file picker. Select Import report. Check that the case shows the same ID, component and deployed revision as the source report. 
{
  "id": "CASE_ID",
  "title": "REPORT_TITLE",
  "service": "SERVICE",
  "component": "COMPONENT",
  "revision": "DEPLOYED_REVISION",
  "owner": "TEAM"
}

Upload format. Supply exactly these six fields in one JSON object, up to 1 MiB. Keep credentials, attachments and report bodies on the originating platform.

For scripted intake, use python3 cli.py human import-report report.json with the workspace URL and credential configured.

Import from an API client and map catalog entries

To send one mapped report directly to a private installation, issue a named credential with python3 cli.py identity issue pipeline --role intake --out /private/pipeline.token. Send its bearer token from the intake process to POST /api/import/report on the organization's HTTPS origin. The JSON object must contain exactly id, title, service, revision, component and owner. Keep this role on the private workspace.

The customer supplies a private catalog mapping report IDs or scoped assets to a service, component, deployed revision and owning team. Unmapped reports are skipped. A source report keeps its provider identity. Attachments, payments and researcher correspondence stay on the bounty platform.

Map a disclosed report

Save your catalog as private/catalog.json. Replace PROGRAM_HANDLE and REPORT_ID with the program handle and numeric ID of the disclosed report. Fill in the deployment and team from your own inventory. 

{
  "program": "PROGRAM_HANDLE",
  "reports": {
    "REPORT_ID": {
      "service": "SERVICE",
      "component": "COMPONENT",
      "revision": "DEPLOYED_REVISION",
      "owner": "TEAM"
    }
  }
}
python3 cli.py import-disclosed --program PROGRAM_HANDLE \
  --report-id REPORT_ID --catalog private/catalog.json
HackerOne customer program

Set HACKERONE_API_USER and HACKERONE_API_TOKEN through your secret manager. Use a catalog with your program handle and report IDs or asset identifiers. The importer accepts triaged, retesting and resolved reports. 

python3 cli.py sync --program YOUR_HANDLE \
  --catalog private/catalog.json

For signed deliveries, set ICHNIX_PROGRAM, ICHNIX_CATALOG and ICHNIX_WEBHOOK_SECRET on the console. Register /hooks/hackerone on its HTTPS origin. HackerOne customer API · HackerOne webhook verification

Bugcrowd engagement

Set BUGCROWD_API_TOKEN to your read-only customer credential in token-id:token-secret format. Set the catalog’s program to the engagement code. Use submission UUIDs in reports or target UUIDs in assets. The importer accepts triaged, unresolved and resolved submissions and skips duplicates. 

python3 cli.py sync-bugcrowd --engagement YOUR_CODE \
  --catalog private/bugcrowd.json

Set ICHNIX_BUGCROWD_ENGAGEMENT, ICHNIX_BUGCROWD_CATALOG and ICHNIX_BUGCROWD_WEBHOOK_SECRET on the console alongside the API token. Register submission.created and submission.updated at /hooks/bugcrowd. The receiver verifies the signature, then fetches current submission metadata and checks its engagement. Bugcrowd API guide · Bugcrowd webhook verification

A private program requires credentials for your organization’s own engagement. Confirm that a signed delivery creates the expected case in your workspace before enabling routine intake.

05Set up MCP for a coding agent

The Model Context Protocol (MCP) lets a coding agent read case evidence through tools supplied by Ichnix. The client starts Ichnix as a subprocess and exchanges messages over standard input and output.

1. Choose an access profile

  • Remote worker

    Choose this for a teammate’s agent. Its named worker token gives it the case assigned by a time-limited lease.

  • Local reader

    Choose this for a trusted operator on the graph host. The reader can list cases and read context across that graph.

Administrator · issue a worker token

Issue the credential on the host running the private workspace, using its existing identity registry. For the desktop Compose setup, run this from the checkout: 

docker compose --env-file examples/desktop.env exec -T console python3 cli.py identity issue coding-worker --role worker --out /var/lib/ichnix/coding-worker.token

For native Linux with the storage environment configured, run: 

python3 cli.py identity issue coding-worker --role worker --out "$ICHNIX_STATE_DIR/coding-worker.token"

Deliver the token to the worker through your organization's secret manager. Give each worker its own name. To withdraw access, run python3 cli.py identity revoke coding-worker against the same registry.

2. Register the server in your agent

On the computer that runs the agent, open the repository folder. The configuration generator uses this checkout and your Python interpreter. Choose the profile that matches the access you have.

The generator writes a new file. For an existing client configuration, choose an unused output filename, then copy the generated entry into the client configuration.

Remote worker · generate and load a client profile

Windows with Codex. In PowerShell 7+, replace the URL with your private workspace origin. Add --hosted to the generator command if the URL uses the Vercel organization relay. 

py -3 cli.py mcp-config --profile worker --token-env ICHNIX_WORKER_TOKEN --workspace-url https://workspace.example.org --format codex --out ichnix-mcp.toml

Merge the generated tables into your Codex user configuration, ~/.codex/config.toml by default. Start a fresh Codex session from the shell holding the worker token: 

$env:ICHNIX_WORKER_TOKEN = [System.Net.NetworkCredential]::new('', (Read-Host 'Worker token' -AsSecureString)).Password
try {
  codex
} finally {
  Remove-Item Env:ICHNIX_WORKER_TOKEN
}

macOS or Linux with a JSON client. Save the worker token in a private file and replace the URL, adding --hosted for the Vercel relay. 

chmod 600 "$HOME/.config/ichnix/worker.token"
python3 cli.py mcp-config --profile worker \
  --workspace-url https://workspace.example.org \
  --worker-token-file "$HOME/.config/ichnix/worker.token" \
  --out ichnix-mcp.json

Merge the generated mcpServers entry into your client’s MCP configuration, then restart the client. For Codex on these systems, add --format codex and choose a .toml output file instead.

When connected, the client lists claim_review, get_review_context and finish_review. If discovery fails, check the worker role, workspace origin and relay setting. Remote origins require HTTPS. Direct loopback connections can use HTTP.

Local reader · connect on the graph host

Run this in the same environment as the workspace operator. The graph token file must exist and be readable only by its owner. This command uses the workspace’s configured HydraDB URL and token file. 

python3 cli.py mcp-config --profile local --out ichnix-reader.json

Merge the generated entry into your JSON client’s MCP configuration and restart the client. Ask it to call list_cases, then get_case_context with a returned case ID.

3. Give a worker its first review

Queue a case and verify the handoff
  1. Queue a review on the workspace host.

    Replace CASE_ID with an imported case. Save the job ID from the response. 

    python3 cli.py handoff enqueue CASE_ID owner-review
  2. Open the agent.

    Ask it to call claim_review, read the assigned case with get_review_context, then call finish_review with its job ID. The worker can record needs-owner-review. A human reviewer makes the ownership decision.

  3. Check completion on the host. 
    python3 cli.py handoff status JOB_ID

For Compose, prefix the host commands with docker compose --env-file examples/desktop.env exec -T console. Use evidence-review for cases with staging observations. That worker can record evidence-reviewed or needs-evidence.

To queue work automatically after intake and CI, set ICHNIX_AUTO_HANDOFFS=1 on the console, CLI and intake processes. All three must share the same handoff store.

Give an agent a compact report README

Open a case in your private workspace and select Download report README below the case heading. A read, review or intake credential can download the six mapped fields as README.md. Worker access stays scoped to an active lease.

To export the same fields on the workspace host, use the case ID shown in the console and choose a new file in an existing private directory. 

mkdir -p -m 700 private
python3 cli.py export-readme CASE_ID --out private/README.md
  • Local MCP reader. Call get_case_context with {"case_id":"CASE_ID","format":"markdown"}.
  • Leased MCP worker. Call get_review_context with your claimed job_id and format: "markdown". To submit a disposition, first read the full evidence context using the same tool without the format option.

Starting from a document? On your Linux workspace with the optional dependencies or inside the supplied container, convert a local Office document or text-based PDF to Markdown before reviewing it. 

python3 cli.py document-readme source.docx --out private/source.md

The AnyDoc converter runs locally with OCR disabled. Input is limited to 8 MiB and output to 256 KiB. The resulting document can contain the full original report. Review it before sharing it with an agent. The browser uploader accepts the six-field JSON format.

06Capture CI evidence

Have your deployment pipeline export environment set to staging, its service and revision, and a settings object. In a separate policy, map each service to the expected boolean, integer or string settings. See examples/staging.json and examples/policy.json in the checkout.

Give CI and intake private files with the same 32–1024 random bytes. Set ICHNIX_CI_HMAC_KEY_FILE to the appropriate file on each host. Sign the exact manifest bytes in CI, then transfer the manifest and detached signature to the workspace.

Replace CASE_ID with the case for this deployment. Sign in CI, then run the second command on the workspace host. 

python3 cli.py staging --sign \
  --manifest private/staging.json --out private/staging.sig

python3 cli.py staging CASE_ID \
  --policy private/policy.json --manifest private/staging.json \
  --signature private/staging.sig --run-id RUN_ID

Use your pipeline’s run identifier for RUN_ID. Reuse that identifier to retry the same CI observation. Evidence includes its revision, result, source digest and verification method. Exit 0 means all configured values matched, 1 means a value differed or was missing, and 2 means intake could not complete. A missing setting appears as inconclusive. Open the evidence trace to see checks from the latest run. Checks from one manifest appear together, grouped by result. Single observations and mixed sources appear in recorded order.

A signed manifest attests to bytes provided by the holder of the shared key. A review records an owner decision. The original bounty finding requires independent verification by the security team.

07Configure storage

For a new named deployment, set both database paths on the console host. HydraDB stores cases and evidence. SQLite stores hashed identities and durable review leases. All console and intake processes for that organization should share the same local files. 

export ICHNIX_STATE_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/ichnix"
export ICHNIX_IDENTITY_DB="$ICHNIX_STATE_DIR/identities.sqlite3"
export ICHNIX_HANDOFF_DB="$ICHNIX_STATE_DIR/handoffs.sqlite3"
python3 cli.py storage init
python3 cli.py storage check
python3 cli.py check-workspace
Optional · archive mapped reports to Amazon S3 or Cloudflare R2

Use an object store when your organization needs a separate copy of the six mapped report fields. HydraDB still holds the case history and SQLite still holds identities and leases.

  1. Create a private bucket for this workspace. Set its retention policy and grant the console permission to put objects under reports/.
  2. On the private console host, set ICHNIX_ARCHIVE_BUCKET to the bucket name. For Amazon S3, set AWS_DEFAULT_REGION to the bucket region. For R2, use auto and set ICHNIX_ARCHIVE_ENDPOINT to the S3 API endpoint shown in the R2 dashboard.
  3. Supply credentials through a workload role supported by the SDK, or inject AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY from your secret manager. Include AWS_SESSION_TOKEN for temporary credentials. For Docker, export these settings in the shell that launches Compose, then enable the archive override: 
    docker compose -f compose.yaml -f examples/compose.archive.yaml --env-file examples/desktop.env up -d --wait
    Use the same files when recreating that service. The base Compose setup leaves archive settings outside the container.
  4. Import a mapped report. In the bucket, look for reports/<sha256>/README.md. Identical mapped fields share one object. Changed fields produce a different digest.

A configured archive receives its copy before HydraDB publishes the case. If intake fails, restore archive and graph access and retry the same report. An object can already exist when the graph write needs a retry.

The Docker image includes the optional dependencies. For native Ubuntu, use a virtual environment and install python3 -m pip install --only-binary=:all: --require-hashes -r extras/report-requirements.txt before starting the console.

Existing deployments and Compose

Initialization is idempotent. The check reads database integrity and schemas. For an existing deployment, keep its original paths. For Compose, export the corresponding paths under /var/lib/ichnix, then use docker compose run --rm console python3 cli.py storage init before startup. Keep the console state volume across restarts.

Recover a private workspace

Stop all writers, including external CLI jobs. Shut down both Compose services with docker compose down, keeping their volumes. From the same shutdown point, back up graph_data, graph_auth and console_data with numeric ownership and modes intact. Keep encrypted backups under separate access control. Back up the external configuration and secret-manager references separately.

Restore into three empty volumes for a separately named Compose project on an isolated host. Start the pinned image with the original settings. Run python3 cli.py storage check inside the console, open a known case, and check a queued handoff. A snapshot restores access as of its capture time. Reapply later revocations and rotations before admitting users or reconnecting providers.

08Connect the hosted organization workspace

Give your team a private sign-in at /workspace. The public demo at /console uses a separate origin.

Connect the private origin
  1. Set ICHNIX_WORKSPACE_ORIGIN in Vercel to the HTTPS root of the organization installation.
  2. Set ICHNIX_ORIGIN_SECRET to the same random secret of at least 32 characters on Vercel and the origin. Require the relay’s X-Ichnix-Origin-Secret header on the origin.
  3. Apply production values only to deployments trusted to access the organization.
Sign in, upload and connect a worker

Sign in with a named organization credential. The relay forwards it to the organization API. Readers can open cases, reviewers can record decisions, and intake credentials can upload one report at a time.

For remote workers, use a named worker credential and the hosted client settings.

Receive signed platform events

Register /hooks/hackerone or /hooks/bugcrowd on the Vercel hostname. Configure the program, catalog and signing secrets on the private origin. The relay preserves the signed bytes for verification.

Webhooks and mapped uploads accept up to 1 MiB. Review decisions accept up to 16 KiB.

Vercel serves the website. A persistent host runs HydraDB, SQLite and the read-only demo.

  1. Import the repository into Vercel and select main as the production branch. The included vercel.json configures the build and functions.
  2. On the persistent host, start the demo: 
    python3 cli.py demo --public-readonly --port 18766
  3. Expose the demo over HTTPS. Set ICHNIX_PUBLIC_ORIGIN in Vercel to its origin, without a path or credentials.
Configure Workers AI layout selection

Enable this option to let Workers AI choose how to lay out a report diagram. The model receives only the report’s source and topic categories.

  1. In Vercel

    Set ICHNIX_CF_ACCOUNT_ID and ICHNIX_CF_AI_TOKEN. Generate a random shared secret of at least 32 characters and set it as ICHNIX_LAYOUT_SECRET.

    Set ICHNIX_LAYOUT_URL to your HTTPS Vercel URL ending in /api/report-layout. Store the same secret in a private file and point ICHNIX_LAYOUT_SECRET_FILE at it.

10Export evidence to SelfGraph

Hand an agent the observed CI checks for one case revision. In the public console, open a case and select Download SelfGraph facts. In a private workspace, run the exporter on the operator host. Replace CASE_ID with the identifier shown in the console. Write the export to a new file in a private directory. 

python3 cli.py export-selfgraph CASE_ID --out "$HOME/case.facts.json"

The CLI receipt reports entity and relation counts. The file contains the case ID, service, component revision and recorded check results, with run IDs and manifest digests when available. Re-export after new CI observations. Deployments retain distinct snapshot IDs on remapping. A local MCP reader can call get_case_context with format: "selfgraph" for the same facts.

Import and query with SelfGraph 0.2.0

Install the optional SDK in a virtual environment on the receiving machine. Point it at that organization's self-hosted HydraDB Bolt endpoint and set SELFGRAPH_AUTH through your secret manager. Use a dedicated destination namespace for each source workspace. Configure TLS for remote connections. The commands below use the native loopback listener. Replace YOUR_NAMESPACE with the destination namespace and CASE_ID with the exported case identifier. 

python3 -m venv .venv
.venv/bin/pip install selfgraph==0.2.0
export SELFGRAPH_STORE=hydradb SELFGRAPH_URI=bolt://127.0.0.1:7687
export SELFGRAPH_NAMESPACE=YOUR_NAMESPACE
.venv/bin/selfgraph insert facts "$HOME/case.facts.json"
.venv/bin/selfgraph readiness
.venv/bin/selfgraph check-answerable "Which observations belong to CASE_ID?" --term CASE_ID

Answerability checks whether terms connect to recorded facts. Inspect the observation's result to distinguish a pass, failure or inconclusive check. Importing the same file again reuses the same identifiers. Source references describe provenance; private manifests stay with the operator. SelfGraph SDK

11Understand the graph

HydraDB links a report to a service-specific snapshot, the exact component revision, its CI observations and owner reviews. When another case uses that component revision, a traversal retrieves prior outcomes. Those earlier decisions and checks inform the next review.

Owner ranking
The catalog owner starts with one positive vote. For each candidate, the score is (accepted + 1) / (accepted + rejected + 2). Later decisions update the ranking while the case keeps its decision history.
CI check ranking
A failed check contributes two points, a passed check one and an inconclusive check zero. Each other snapshot contributes at most its strongest observation for that check. The ranking suggests which existing control to inspect.
Related titles
Normalized sparse character-trigram vectors are stored as graph properties. A revision-scoped traversal selects up to 128 current reports. Application code ranks them by cosine similarity and returns up to five above the threshold. Similar wording alone cannot establish a common cause.

One console host coordinates leases in a private SQLite file. HydraDB holds the evidence and relationships. Use local durable storage for the registry and queue, and retain the graph store and authentication material in your backup plan.
