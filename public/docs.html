Follow a finding

Trace the synthetic ledger retention case from its scope in the catalog to the worker’s decision.

  1. Locate the deployment. SURVEY-101 maps to the ledger service’s archive component at revision r7. The report and its CI observations share that snapshot.
  2. Inspect the evidence. Retention is 60 days against a 30-day policy. Auditing passes. The manifest omits identifier masking, so the check stays inconclusive. A signature authenticates the manifest’s source. A reviewer still assesses the original finding.
  3. Record the outcome. The evidence worker claims a scoped lease and records needs-evidence. Later reviewers can retrieve that outcome from the same snapshot.

Self-host a workspace

Use one installation per organization. Run the following from your checkout on Ubuntu 24.04 x86-64 with Python 3.12, Node 24 and pnpm 12. The installer verifies a pinned HydraDB distribution. 

pnpm install --frozen-lockfile
python3 scripts/install-hydra.py
scripts/start-hydra.sh

Leave the graph running. In a second terminal, start the console. Open http://127.0.0.1:8765/console and enter the token from the private file printed by the launcher. 

scripts/console.sh

In another terminal, check graph access and the local Pele trace renderer. 

python3 cli.py check-workspace

The default state directory is ~/.local/state/ichnix. Set ICHNIX_STATE_DIR consistently to move it. For an existing graph, configure ICHNIX_HYDRA_URL, ICHNIX_HYDRA_TOKEN_FILE, ICHNIX_HYDRA_NAMESPACE, ICHNIX_HYDRA_GRAPH and ICHNIX_HYDRA_CELL. Use authenticated HTTPS for remote connections.

Container deployment 
docker compose up --build --detach --wait
docker compose ps

Compose targets Linux amd64. It binds the console to loopback and keeps graph data, authentication material and console state in named volumes. Put an HTTPS reverse proxy in front of the console for remote staff. For a disposable, read-only sample workspace, use python3 cli.py demo --public-readonly.

Host a public preview on Vercel

Import the Git repository from the Vercel dashboard and set the production branch to main. The root vercel.json builds the public site and three Node functions when Vercel receives Git updates. The graph runtime, SQLite stores and private operator console stay on the workspace host.

Run python3 cli.py demo --public-readonly --with-disclosure --port 18766 on a persistent host. Expose that read-only demo through HTTPS and set its exact origin as ICHNIX_PUBLIC_ORIGIN in Vercel. Leave credentials and paths out of the origin. The relay checks public demo mode and forwards only the published case, diagram, acceptance and evaluation routes. Signed-in company workflows can use a separately configured private organization origin.

For optional AI layout selection, configure ICHNIX_CF_ACCOUNT_ID, ICHNIX_CF_AI_TOKEN and a random ICHNIX_LAYOUT_SECRET of at least 32 characters in Vercel's server environment. On the private ingestion service configure ICHNIX_LAYOUT_URL to the HTTPS Vercel /api/report-layout URL and ICHNIX_LAYOUT_SECRET_FILE to a private file holding the shared secret. The model receives only the report-source and topic categories and selects a three-way display order. The private workspace retains the report text. Missing credentials or an unavailable provider leave the deterministic local ordering in effect.

Connect the hosted organization workspace

In Vercel, set ICHNIX_WORKSPACE_ORIGIN to the HTTPS root of a dedicated persistent organization installation and ICHNIX_ORIGIN_SECRET to a random secret of at least 32 characters. Configure the matching secret on that origin and require the relay’s X-Ichnix-Origin-Secret header. Keep this deployment and its data separate from the read-only demo. Apply production values only to deployments trusted to access this organization.

Sign in at /workspace using a named organization credential. The hosted relay forwards a bearer credential to the organization API for case reads, owner reviews and single-report intake. A named intake credential is required to upload. The public demo at /console stays anonymous. Workers continue to use the private service’s dedicated handoff API.

For platform events, register /hooks/hackerone or /hooks/bugcrowd on the Vercel hostname. Configure the provider signing secrets, organization program scope and catalog on the private origin as described under Connect a program. The relay preserves the signed delivery bytes and signature for verification by that origin. Webhooks and mapped uploads accept up to 1 MiB. Review decisions accept up to 16 KiB.

Configure SQLite

For a new named deployment, set both database paths on the console host. HydraDB stores cases and evidence. SQLite stores hashed identities and durable review leases. All console and intake processes for that organization should share the same local files. 

export ICHNIX_STATE_DIR="$HOME/.local/state/ichnix"
export ICHNIX_IDENTITY_DB="$ICHNIX_STATE_DIR/identities.sqlite3"
export ICHNIX_HANDOFF_DB="$ICHNIX_STATE_DIR/handoffs.sqlite3"
python3 cli.py storage init
python3 cli.py storage check
python3 cli.py check-workspace

Initialization is idempotent. The check reads database integrity and schemas. For an existing deployment, keep its original paths. For Compose, export the corresponding paths under /var/lib/ichnix, then use docker compose run --rm console python3 cli.py storage init before startup. Keep the console state volume across restarts.

Run acceptance

After installing the local runtime, run a complete review in a disposable workspace. This command needs internet access to HackerOne and works without a provider account. 

python3 cli.py acceptance

Public source. The importer retrieves the disclosed title and report ID from curl’s HackerOne program. The public website representation can change independently of the authenticated customer API. HackerOne disclosure #2236133 · curl advisory

Local evidence. The run assigns a local service and owner, observes three HTTP headers on its own Ichnix instance, signs the staging manifest, checks the results, and records a completed MCP handoff and reviewer decision. Its receipt identifies the service under test, observation time, manifest digest and outcome. Exit code 0 means these checks passed. The run makes no measurement of curl’s deployment.

The public preview serves a filtered acceptance receipt. On a self-hosted workspace, use the command above to generate your own receipt.

Connect a program

To send one mapped report directly to a private installation, issue a named credential with python3 cli.py identity issue pipeline --role intake --out /private/pipeline.token. Send its bearer token from the intake process to POST /api/import/report on the organization's HTTPS origin. The JSON object must contain exactly id, title, service, revision, component and owner. Keep this role on the private workspace.

The customer supplies a private catalog mapping report IDs or scoped assets to a service, component, deployed revision and owning team. Unmapped reports are skipped. A source report keeps its provider identity. Attachments, payments and researcher correspondence stay on the bounty platform.

Map a disclosed report

Save this example as private/catalog.json. Its service, component, revision and owner describe a local review workspace. 

{
  "program": "curl",
  "reports": {
    "2236133": {
      "service": "local-acceptance-console",
      "component": "local-http-response",
      "revision": "local-acceptance-v1",
      "owner": "acceptance-reviewer"
    }
  }
}
python3 cli.py import-disclosed --program curl \
  --report-id 2236133 --catalog private/catalog.json
python3 cli.py context h1-curl-2236133
HackerOne customer program

Set HACKERONE_API_USER and HACKERONE_API_TOKEN through your secret manager. Use a catalog with your program handle and report IDs or asset identifiers. The importer accepts triaged, retesting and resolved reports. 

python3 cli.py sync --program YOUR_HANDLE \
  --catalog private/catalog.json

For signed deliveries, set ICHNIX_PROGRAM, ICHNIX_CATALOG and ICHNIX_WEBHOOK_SECRET on the console. Register /hooks/hackerone on its HTTPS origin. HackerOne customer API · HackerOne webhook verification

Bugcrowd engagement

Set BUGCROWD_API_TOKEN to your read-only customer credential in token-id:token-secret format. Set the catalog’s program to the engagement code. Use submission UUIDs in reports or target UUIDs in assets. The importer accepts triaged, unresolved and resolved submissions and skips duplicates. 

python3 cli.py sync-bugcrowd --engagement YOUR_CODE \
  --catalog private/bugcrowd.json

Set ICHNIX_BUGCROWD_ENGAGEMENT, ICHNIX_BUGCROWD_CATALOG and ICHNIX_BUGCROWD_WEBHOOK_SECRET on the console alongside the API token. Register submission.created and submission.updated at /hooks/bugcrowd. The receiver verifies the signature, then fetches current submission metadata and checks its engagement. Bugcrowd API guide · Bugcrowd webhook verification

Private program sync and signed webhook behavior have been checked with provider-shaped fixtures. Live customer onboarding requires credentials for the organization’s own program.

Capture CI evidence

Have your deployment pipeline export environment set to staging, its service and revision, and a settings object. In a separate policy, map each service to the expected boolean, integer or string settings. See examples/staging.json and examples/policy.json in the checkout.

Give CI and intake private files with the same 32–1024 random bytes. Set ICHNIX_CI_HMAC_KEY_FILE to the appropriate file on each host. Sign the exact manifest bytes in CI, then transfer the manifest and detached signature to the workspace. 

python3 cli.py staging --sign \
  --manifest private/staging.json --out private/staging.sig

python3 cli.py staging h1-curl-2236133 \
  --policy private/policy.json --manifest private/staging.json \
  --signature private/staging.sig --run-id pipeline-104

Use the same run ID to retry the same CI observation. Evidence includes its revision, result, source digest and verification method. Exit 0 means all configured values matched, 1 means a value differed or was missing, and 2 means intake could not complete. A missing setting appears as inconclusive. The console displays the latest run as a Pele sequence diagram.

A signed manifest attests to bytes provided by the holder of the shared key. A review records an owner decision. The original bounty finding requires independent verification by the security team.

Connect people and coding agents

Human readers and reviewers can use the web console or the HTTP-backed CLI. Save their named token in a private file. The human CLI uses the console API and works without a graph credential. 

export ICHNIX_WORKSPACE_URL=https://workspace.example.org
export ICHNIX_USER_TOKEN_FILE="$HOME/.config/ichnix/reviewer.token"
python3 cli.py human cases
python3 cli.py human context CASE_ID
python3 cli.py human review CASE_ID TEAM --accept --request-id review-001
Agent profiles

Named identities support four roles. A read credential opens case context. A review credential can also accept or reject an owner. A worker credential can claim, read and finish a leased review. An intake credential can read cases and import one mapped report. Worker context omits related report titles and reviewer history.

Issue credentials on the console host 
state="$HOME/.local/state/ichnix"
export ICHNIX_IDENTITY_DB="$state/identities.sqlite3"
python3 cli.py identity issue analyst --role review \
  --out "$state/analyst.token"
python3 cli.py identity issue coding-worker --role worker \
  --out "$state/coding-worker.token"
python3 cli.py identity list
python3 cli.py console --port 8765

Start the console in this environment with the port free. Registry mode accepts named tokens and disables the shared operator token. Each review records its actor and UTC timestamp. To withdraw worker access, run python3 cli.py identity revoke coding-worker.

Configure stdio on the worker machine

Transfer only that worker’s credential through your secret manager. Place it in a private file readable by the worker. From the worker’s checkout, generate a client configuration with absolute paths valid on that machine. 

python3 cli.py mcp-config --profile worker \
  --workspace-url https://ichnix.example.org \
  --worker-token-file "$HOME/.config/ichnix/worker.token" \
  --out ichnix-mcp.json

Use the generated mcpServers entry in a compatible JSON stdio client. For Codex, use --format codex --out ichnix-mcp.toml and add that table to the client configuration. The profile references a credential file. Its contents and each lease secret stay outside the model context. Remote origins require HTTPS. Loopback HTTP works for a local session.

Queue one review

Manual handoffs are the default. To queue reviews automatically after intake and CI, set ICHNIX_AUTO_HANDOFFS=1 on the console, CLI and intake processes and point all three at the same private state directory. 

python3 cli.py handoff enqueue h1-curl-2236133 owner-review
python3 cli.py handoff status JOB_ID

Use evidence-review when the case already has staging observations. Ask the agent to call claim_review, pass the returned job ID to get_review_context, inspect the material, then call finish_review. For an evidence review, pass the optional disposition value evidence-reviewed or needs-evidence. An owner review accepts needs-owner-review. The graph records these outcomes against the reviewed snapshot. Only reviewer decisions change owner rankings. Unfinished leases expire and become available again. A completed handoff leaves the owner decision to the reviewer.

For a trusted local operator, python3 cli.py mcp-config --profile local --hydra-token-file /private/hydra-token generates a direct graph-reader profile. It offers list_cases and get_case_context. MCP lifecycle and version negotiation

Export evidence to SelfGraph

Hand an agent the observed CI checks for one case revision. In the public demo, select IX-108 and download its SelfGraph facts. For a private workspace, run the exporter on the operator host. The destination must be a new file in a private directory. 

python3 cli.py export-selfgraph IX-108 --out "$HOME/ix-108.facts.json"

The CLI receipt reports entity and relation counts. The file contains the case ID, service, component revision and recorded check results, with run IDs and manifest digests when available. Re-export after new CI observations. Deployments retain distinct snapshot IDs on remapping. A local MCP reader can call get_case_context with format: "selfgraph" for the same facts.

Import and query with SelfGraph 0.2.0

Install the optional SDK in a virtual environment on the receiving machine. Point it at that organization's self-hosted HydraDB Bolt endpoint and set SELFGRAPH_AUTH through your secret manager. Use a dedicated destination namespace for each source workspace. Configure TLS for remote connections. The example uses the native loopback listener. 

python3 -m venv .venv
.venv/bin/pip install selfgraph==0.2.0
export SELFGRAPH_STORE=hydradb SELFGRAPH_URI=bolt://127.0.0.1:7687
export SELFGRAPH_NAMESPACE=ichnix-ledger
.venv/bin/selfgraph insert facts "$HOME/ix-108.facts.json"
.venv/bin/selfgraph readiness
.venv/bin/selfgraph check-answerable "Is there a retention check for IX-108?" --term IX-108 --term retention_days

Answerability checks whether terms connect to recorded facts. Inspect the observation's result to distinguish a pass, failure or inconclusive check. Importing the same file again reuses the same identifiers. Source references describe provenance; private manifests stay with the operator. SelfGraph SDK

Understand the graph

HydraDB links a report to a service-specific snapshot, the exact component revision, its CI observations and owner reviews. When another case uses that component revision, a traversal retrieves prior outcomes. This is the learning loop for Track 1, the self-improving graph.

Owner ranking
The catalog owner starts with one positive vote. For each candidate, the score is (accepted + 1) / (accepted + rejected + 2). Later decisions update the ranking while the case keeps its decision history.
CI check ranking
A failed check contributes two points, a passed check one and an inconclusive check zero. Each other snapshot contributes at most its strongest observation for that check. The ranking suggests which existing control to inspect.
Related titles
Normalized sparse character-trigram vectors are stored as graph properties. A revision-scoped traversal selects up to 128 current reports. Application code ranks them by cosine similarity and returns up to five above the threshold. Similar wording alone cannot establish a common cause.

One console host coordinates leases in a private SQLite file. HydraDB holds the evidence and relationships. Use local durable storage for the registry and queue, and retain the graph store and authentication material in your backup plan.

Read the measurements

Retrieval on synthetic cases

Six held-out cases share three component revisions. Feeding separate labeled cases to the same graph increases top-ranked owner and CI-check accuracy from 0/6 to 2/6, 4/6 and 6/6. The catalog owner alone gets 0/6. Pooling the same training feedback across all components, with the same ranking code, scores 0/6, 2/6, 2/6 and 2/6 on both tasks. Only training cases receive owner decisions and CI observations. This comparison measures the value of component-scoped feedback on recurring workflows within HydraDB. 

python3 cli.py evaluate --clients 16 --requests 128
How a product security team could evaluate a pilot

The proposed buyer is the product security lead who runs a bounty program across several engineering teams. Start with one program and track the share of reports the first assigned team accepts, reassignments per report, and median time from triage to owner acceptance. Compare with the team's existing process on comparable reports. The synthetic benchmark measures routing accuracy. A customer pilot would establish time savings and willingness to pay.

Coding-agent compatibility

Two Codex CLI sessions used separate worker credentials. The evidence inspector identified a failed retention control and missing masking evidence. The owner router retrieved the records team and the prior retention check. Each session claimed one job and recorded its disposition in one attempt. Both SQLite receipts matched their HydraDB outcomes.
